## 二、方案选择
- **发布**：GitHub Pages（仓库 `Personal_website` 的 `main` 分支根目录）

- **后端**：Supabase（托管 Postgres + 自带 REST API）
  - 理由：不需要自己写接口；前端用 `fetch` 直接写库，无第三方 SDK、无构建步骤
  - 前端只用到两个值：项目 URL 和 `anon public` key（都写在 `js/feedback.js` 顶部）

## 四、表单行为说明
- **字段**：Name（可选）、Email（可选）、Message（必填，最多 2000 字）
- **校验**（都在浏览器里先做，不浪费一次请求）：
  - Message 为空 → `Please write a message first.`
  - Message 超过 2000 字 → `Message is too long (2100/2000).`
  - Email 填了但格式不对 → `That email address looks incomplete.`
- **蜜罐反垃圾**：表单里藏了一个 `#fb-website` 输入框（访客看不见）。
  机器人会把它填上 → 前端假装成功（显示 `Thanks!`）但**不发送任何数据**。
- **未配置 Supabase 时**：不报错，改为打开访客的邮件客户端，把内容预填成发往
  `xk_yyy@outlook.com` 的邮件，提示 `Opening your email app...`。
  所以**在你填好配置之前，留言也不会丢**。
- **发送失败时**（网络问题 / 权限问题）：提示 `Could not send right now. Please email ...`
  并重新启用按钮，不会把人卡在 "Sending..."。

### 礼花动画（提交成功时）
- **只在数据真的写入成功时播放**。蜜罐假成功（给机器人看的）和邮件降级都**不放**，
  因为那两种情况并没有真的保存。
- 实现：`js/confetti.js`，用原生 `<canvas>` 画约 110 片纸屑，从提交按钮位置向外上方
  绽放，有重力、空气阻力和翻转效果。约 2 秒后自动消失。
- **不引第三方库**：整个效果约 200 行原生 JS，符合本项目「无依赖、无构建」的约定。
- **播完自动清理**：canvas 会从 DOM 里移除，页面空着的时候不多留一层。
- **永远不会挡住点击**：图层是 `pointer-events: none`，并且 `aria-hidden="true"`，
  读屏软件不会念它。
- **尊重系统「减少动态效果」设置**：开了这个选项的访客**完全看不到礼花**
  （直接跳过），但成功提示照常显示——那才是真正的确认。
- **礼花是加分项，不是必需品**：就算 `confetti.js` 加载失败，表单照常提交成功
  （代码里用 `typeof window.confettiBurst === "function"` 做了保护）。

## 六、接入 Supabase（本项目已完成，换新项目时按此操作）
1. 到 https://supabase.com 注册 / 登录，**New project**（区域选离你近的，比如 Singapore）
2. 项目建好后，左侧 **SQL Editor** → **New query**
3. 把 `docs/supabase-feedback.sql` 的全部内容粘进去 → **Run**
   （执行完可以在 **Table Editor** 里看到 `feedback` 表）
4. 左侧 **Project Settings** → **API**，复制这两个值：
   - **Project URL**（形如 `https://abcdefghijklm.supabase.co`）
   - **Project API keys** 里的 **`anon` `public`** 那一条
5. 把这两个值填进 `js/feedback.js` 顶部的 `SUPABASE_URL` 和 `SUPABASE_ANON_KEY`
   （本项目**已完成**；换新项目时改这两行即可）

> **这两个值可以公开**（会出现在前端源码里，这是 Supabase 的正常用法）。
> 安全性靠 `docs/supabase-feedback.sql` 里的 RLS 策略保证：
> 匿名角色只有 `insert` 权限，**没有 `select`**，所以别人拿这个 key 也读不到留言。
> 但注意：**`service_role` key 绝对不能放进前端**，那是管理密钥。

### 查看收到的留言
Supabase → **Table Editor** → `feedback` 表。按 `created_at` 倒序排列就是最新的留言。
也可以在 **SQL Editor** 里跑：

```sql
select created_at, name, email, message
from public.feedback
order by created_at desc;
```

## 八、遇到的问题

### 总览：接 Supabase 时连撞三个坑
前端界面只会把真实错误丢进 `console.warn`，所以**一定要直接打接口看响应体**
才能定位。用 `curl` 打一次 `/rest/v1/feedback` 就够：

```bash
curl -i -X POST "https://<项目ref>.supabase.co/rest/v1/feedback" \
  -H "apikey: <你的key>" \
  -H "Authorization: Bearer <你的key>" \
  -H "Content-Type: application/json" \
  -H "Prefer: return=minimal" \
  --data-binary '{"name":"t","email":"","message":"hello"}'
```

依次撞到的是：

| 次序 | 报错 | 缺什么 |
| --- | --- | --- |
| 1 | `PGRST204 Could not find the 'page' column` | 表缺列 |
| 2 | `42501 permission denied for table feedback` | 缺 `GRANT` |
| 3 | `42501 new row violates row-level security policy` | 缺 RLS 策略 |

三个都修完后 → `HTTP 201 Created`。**Grant 和 RLS 是两层、缺一不可**：

```
浏览器请求（anon 身份）
   ├─ ① GRANT 检查：这个角色能碰这张表吗？   否 → 42501 permission denied
   ├─ ② RLS 检查：能碰的话，允许碰哪些行？   无匹配策略 → 42501 violates RLS
   └─ ③ 通过 → 201 Created
```

- **经验**：PostgREST 的报错提示会直接告诉你当前连接角色叫什么
  （例如 `GRANT INSERT ON public.feedback TO anon;` 里的 `anon` 就是角色名），
  照着提示写就行，不用猜。
- **经验**：改完表结构或权限后跑一句 `notify pgrst, 'reload schema';`，
  否则 PostgREST 的 schema cache 要等一会儿才刷新，很容易误判成「改了没用」。

### 坑一：`PGRST204` 缺少 `page` 列
- **现象**：Supabase 的 URL 和 anon key 都填好了，前端仍然发不出去，
  提示 `Could not send right now. Please email ...`。
- **真实报错**（直接打接口看到的）：
  ```
  HTTP 400  {"code":"PGRST204",
             "message":"Could not find the 'page' column of 'feedback' in the schema cache"}
  ```
  把同一个请求体去掉 `page` 字段后 → `HTTP 201`，说明 key、RLS、表全部正常，
  **只差 `page` 这一列**。
- **原因**：`feedback` 表在建表语句执行**之前就已经存在**了。`create table if not exists`
  遇到已存在的表会**整句跳过**，包括里面新加的列。于是 PostgREST 收到一个未知字段，
  直接把整个请求 400 拒掉。
- **修法**：`docs/supabase-feedback.sql` 已改成「第 2 节会自动补列」的版本，
  对已存在的表也能修复。
- **最终处理**：`page` 字段其实是 `js/feedback.js` 里**写死的常量 `"contact"`**，
  全站只有一个表单，它不携带任何真实信息。既然它添了个没用的列还导致报错，
  索性**直接从提交的 payload 里删掉**，前端不再依赖这一列。数据库里保留该列也无妨
  （有 `default 'contact'`），删掉也不影响。

### 坑二：`42501 permission denied for table feedback`
- **现象**：`drop table` 重建之后，同一个请求从 `201` 变成权限被拒。
- **原因**：通过 Supabase **Table Editor 界面**建表时，平台会自动 Grant；
  而通过 **SQL Editor 手写 `create table`** 时**不会自动 Grant**。
  把旧表 drop 掉重建，就把原来那份自动授权一起弄丢了。
- **修法**：
  ```sql
  grant usage on schema public to anon;
  grant insert on table public.feedback to anon;
  ```
  只给 `insert`，**不给 `select` / `update` / `delete`**——公开的 anon key
  就应该只有写的能力。前端配合使用 `Prefer: return=minimal`，
  这样 PostgREST 写完不回头查表，也就不需要 `select` 权限。

### 坑三：`42501 new row violates row-level security policy`
- **现象**：Grant 之后仍然被拒，报错换成了 RLS。
- **原因**：`drop table` 会**连带删除表上的 RLS policy**，重建表不会把策略带回来。
  于是 RLS 开着、却没有任何策略放行 → 默认全部拒绝。
- **修法**：
  ```sql
  drop policy if exists "anon can insert feedback" on public.feedback;
  create policy "anon can insert feedback"
    on public.feedback
    for insert
    to anon
    with check (true);
  ```

### 教训：不要随手 `drop table`
`drop table` 会同时丢掉 **数据 + GRANT + RLS policy**，重建后要一项项补回来。
`docs/supabase-feedback.sql` 现在是**全程幂等**的（建表 → 补列 → Grant → 策略 →
刷新缓存 → 索引，每步都是 `if not exists` / `drop policy if exists`），
**表结构或权限有任何疑问，直接整份重跑一次**，不要 drop，
也不要一句一句地试——这几轮来回就是一句一句试出来的。

### 成功提示会把提交按钮顶出屏幕（375×667，做礼花时才发现）
- **现象**：在小屏上提交成功后，表单底部从「余量 21px」变成「溢出 18px」，
  提交按钮被顶到可视区外面。做礼花测试时才暴露出来。
- **原因**：`.feedback-actions` 原本是 `flex-wrap: wrap`。成功提示
  `Thanks - your feedback was saved.` 在小屏放不下，就**换行到自己单独一行**，
  瞬间把表单撑高约 39px（16px 的间距 + 约 23px 的一行文字）。
  **这是 V3 表单本来就有的问题，跟礼花无关**——只要提交成功就会出现，
  之前测 375×667 用的是**空状态**，所以一直没暴露。
- **修法**（改 `css/style.css`，两处）：
  1. `.feedback-actions` 改成 `flex-wrap: nowrap`，并给 `.feedback-status`
     加 `flex: 1 1 auto; min-width: 0`——让提示文字**在自己那份宽度里折行**，
     而不是另起一行。
  2. `.feedback-status` 加 `line-height: 1.35`。原本行高是 23.12px（字号 13.6px 的
     1.7 倍，从父级继承来的），两行就有 46.2px，比按钮的 38.2px 还高，仍会撑高 8px。
     收紧到 1.35 后两行是 36.7px，**塞得进按钮高度内**。
- **结果**：位移从 18px 溢出 → 8px → **0px**。提交前后面板高度完全不变，
  按钮始终完整可见。
- **教训**：验收「小屏放得下」时，**一定要把界面的每种状态都测一遍**
  （空状态、成功、报错），只测空状态会漏掉这类「内容出现才撑开」的问题。
  错误提示更长（`Could not send right now. Please email xk_yyy@outlook.com.`），
  在 375px 下会折成 3 行，此时行高 55px > 按钮 38.2px，会撑高约 17px——
  仍在 21px 余量之内，不会溢出。
