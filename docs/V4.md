## 二、方案选择
- **手机端图库**：不再用 4–5 列的胶片条（`FILMSTRIP`），改成**整屏一张的轮播**（`CAROUSEL`），
  桌面端继续保持两行拼贴。理由：胶片条在 375px 宽下每张只剩几十像素，怎么调都不好看；
  整屏一张则和时间轴式的浏览习惯一致，照片也终于看得清。用 `matchMedia` 实时切换，不刷新。
- **图片体积**：新增 720 / 1200 两档派生图，用 `srcset` + `sizes` 让浏览器自己挑。
  理由：手机槽位只有 92vw，不需要 1600px 原图。
- **蓝色底框**：换成**这张照片自己放大 + 模糊后的副本**（`blur(22px) saturate(1.2)`）。
  它复用的就是该 slide 本来就要下载的 720 档文件，**不产生额外请求**。
- **滑动跳页**：`.panel-body` 上 `overscroll-behavior-y: contain`。
  理由：跳到下一页是浏览器的默认「滚动链」行为，不是 bug，所以要在源头掐掉，而不是去补救。
- **AI 分身**：非模态对话框 + 本地知识库；`askAI(text)` 是将来接真实 API 的**唯一接缝**。

## 四、三个问题的实测数据

### ① 照片太小
| | 旧（胶片条） | 新（轮播） |
|---|---|---|
| 最小长边 | 63px | **225px** |
| 最小绘制面积 | 42 × 63 = 2,646px² | **31,500px²** |

### ② 加载不出来
- 手机尺寸下的总下载量：**4.27MB（全部下 1600 原图）→ 993KB（720 档）**。
- 实测 720 档总字节 **993,734 B**，1200 档 **2,464,388 B**；
  375px 宽的手机实际只拉 720 档（`srcset` 生效，实测 `renditions actually used: -720.jpg`）。
- 第一张进入首屏即可见（相框顶部在 667px 视口的 307px 处），无需滚动。
- 轮播的 21 张全部解码成功（21/21），不存在空白框。

### ③ 滑动突然跳页
| 条件 | 同一次滚轮手势后页面位移 |
|---|---|
| `overscroll-behavior-y: contain`（现在） | **0px** |
| 临时改回 `auto`（对照组） | **120px** |
| 面板正文之外（hero）作对照 | 480px |

结论：位移确实来自滚动链，`contain` 把它掐在面板正文里，**桌面端仍保持 `auto`**（`phase-c2` 有断言）。

## 五、模糊背景（为什么那不是边框）
- 相框是 3:2，而竖构图照片（aspect 0.667）塞进去必然留白。旧的留白是**一层平涂的 accent 色**，
  看起来就是「照片被蓝色边框框住」。现在留白处放的是**这张照片自己的虚化放大副本**。
- 判据用**逐列高频细节**（相邻行亮度差绝对值的均值），而不是纵向方差——
  `blur(22px)` 会保留低频明暗渐变，用方差判断会把虚化误判成清晰。
- A/B 实测（竖构图，photo-11）：
  | | 中间清晰带（150px 宽） | 两侧虚化带（各 94px） |
  |---|---|---|
  | 细节值 | **6.89** | **0.96**（差 7 倍） |
  | 颜色 | 照片本身 | 草地 / 树影的绿（虚化的就是这张照片） |
  | **隐藏虚化层后** | 不变 | 塌成 `rgb(25, 28, 34)`，即轨道底色 `#14171d` |
- 反过来，能填满相框的照片（photo-01 的 16:9、photo-03 的 1.4995）**两侧完全没有虚化带**，
  隐藏虚化层后画面分毫不变——说明虚化层只在真的需要补空时才起作用。
- 圆点映射全量验证：21 个圆点逐个点击，**21/21** 都落在正确 slide，
  且与 `CAROUSEL` 数组逐项吻合。

## 六、自动播放与「减少动态效果」
- 轮播/拼贴都是 **2 秒一页**（`INTERVAL = 2000`）。
- **修复**：以前 `prefers-reduced-motion: reduce` 只把滚动从 `smooth` 改成瞬时，
  **轮播照样每 2 秒自己翻页**。现在把判断放进 `start()` 里——
  它是自动播放的**唯一入口**（首屏加载、圆点、箭头、hover/focus 恢复、
  触摸后 3 秒恢复、灯箱关闭都要经过它），一处判断就全覆盖了。
- 于是开了「减少动态效果」的访客：**不会自动翻页**，但圆点、箭头、滑动、灯箱**照常可用**
  （只是移动变成瞬时，这正是这个设置想要的效果）。
- 页面开着时改系统设置也会即时生效（监听 `change`），不用刷新。
- 实测（独立探针，14 项全过）：reduce 下 5.2 秒内 0 次自走；
  点第 4 个圆点仍准确定位到 1013px；点箭头 +1 后停住；切回 `no-preference` 后恢复自动播放；
  不作任何模拟的普通加载仍然每约 2 秒翻一页（没有把默认行为弄坏）。

## 七、AI 分身（模板，未接 API）
- 位置：右下角悬浮按钮，点开是聊天面板。**非模态**（`aria-modal="false"`），
  所以页面其余部分照常可用；`Esc` 关闭，但灯箱打开时让位给灯箱。
- 内容：只回答**页面上真实存在的内容**（10 条本地知识库，来自 About / Research /
  Experience / Projects / Learning / Contact 的实际文案）。答不上来就明说不确定，
  并给出可点的锚点链接。
- 诚实标注：标题下方一直显示 `Template mode · not connected yet`，
  接上真实模型后应删掉这一行。
- 安全：所有回复一律用 `textContent` 写入（不解析 HTML）；外链带
  `target="_blank" rel="noopener"`。
- 接缝：`askAI(text)` 是唯一要改的函数，契约是
  `Promise<{ text: string, links?: [{ label, href }] }>`；目前是 280ms 延时后回放本地答案。
- 代词按作者实际性别（女性）书写，全项目无 `he/him/his` 残留。
